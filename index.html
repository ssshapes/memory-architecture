Memory architecture

The personal OS is a memory prosthesis for a frontier model. The model arrives brilliant and amnesiac: trained on everything in general, knowing nothing about this life in particular, and the particulars change daily. Every organ below closes that gap without guessing a fact, losing a day silently, or believing something it can't source. This is one running instance of a portable pattern; the specifics are examples, the architecture is the point.

The circulation: one prompt, end to end

The problem, precisely

A language model stores distributions, not records. It learns what lighting manufacturers are like from a million exposures; it cannot learn what happened Tuesday from one. So everything specific, the people, projects, deadlines and decisions, has to be retrieved into the context window at the moment of use.

That makes the context window the model's working memory, and in-context learning a temporary weight update: scoped to one session, auditable, reversible. The whole job of the OS is deciding what earns a place in that window, when, and with what proof. Retrieval quality is intelligence here.

The memory taxonomy it serves

Weights
The gist
General knowledge, language, judgment. Learned slowly by the lab, shared by everyone. Nothing personal lives here; it can't be audited or deleted.
Context window
Working memory
Ephemeral and precious; degrades as it fills. Holds the live thread plus whatever the organs inject. Cleared at seams between threads, never mid-thought.
Files + index
Long-term explicit
The corpus: memories, people, projects, doctrine. Every belief is a line with provenance that can be found, corrected or deleted, which weights can never offer.
Ledger data
Never-guess facts
VINs, balances, deadlines, entry numbers. Read from files and systems of record, never generated. A guess here is a failure, not an approximation.

The human analogy runs the same architecture: cortex (weights, slow), working memory (context), hippocampus (episodic capture), sleep (/consolidate), and written records for what the brain should never improvise. Biology retrains nightly and still needs the hippocampus. That is why "just fine-tune the model on my life every night" doesn't dissolve this system: weights can't take one-shot facts, and they can't forget on command.

Inside the stores

The left column of the diagram, opened up. Four stores, four lifecycles. Every shelf answers the same three questions: what context it holds, what triggers its retrieval, and who tends it.

Semantic memory · atomic facts ↑ diagram

One durable fact per file, 225 of them as of 9/3, in four types: user_ (who the principal is), feedback_ (how to work with them, with the why), project_ (ongoing threads), reference_ (where things live). Each file carries its provenance, a one-line hook:, and wikilinks. MEMORY.md is a page derived from these files, not a document anyone edits: rebuilt weekly and after every consolidation, feedback memories pinned, the rest filled to a byte budget by measured use. What misses the page is still found by recall. Retired memories move to an archive tier with a reason and a pointer to what replaced them.

Episodic memory · what happened ↑ diagram

One card per conversation, written when a session ends or compacts: a summary plus who and what was mentioned, with the transcript alongside for verification. Consolidation distills these into memories. Routine automation runs (in this instance, a Sunday brief and a daily news scrape) are gated out, so the store remembers days, not machinery. Known defect, filed 9/1: cards for long sessions run thin on the first hour.

Agent memory · the foreman's notebook ↑ diagram

A smaller memory directory that belongs to one agent. The foreman runs the twice-daily fleet health pass and keeps its notes in .claude/agent-memory/foreman/, apart from the stores above, so housekeeping never surfaces in the principal's sessions as memories about their life.

The corpus · the repo itself ↑ diagram

Everything that isn't a memory file is the corpus: the repository's domain folders, which are the primary record, not documentation of it. Memories mostly point into the corpus; the corpus is where state lives.

people/ · the Rolodex
One file per contact plus a network map with cadences and last touches. Triggered whenever a name appears. Serves the whole OS: school, household, venture threads.
Domain folders · the projects
One folder per domain of the life in question, in this instance properties/ (three of them, personal vs LLC walled off), family/, yale-emba/, ai-development/. Each carries its own CLAUDE.md doc index; the root routing layer sends a topic to its domain instead of loading everything.
knowledge/ · the wiki
Two layers: raw/ keeps sources as they arrived; wiki/ keeps what they were distilled into. Reading flows in by pull, gets a worth-verdict, and only the durable part is kept.
tools/ + routines/ · the machinery
The running surfaces and their specs: this board and its pages, and the source-of-truth definition of every scheduled routine the clock below executes.
index.db · the search layer ↑ diagram

Not a store of beliefs: a derived lookup over the stores above, rebuilt at every session start and queried on every prompt (keyword plus vector, rank-fused, one hop along wikilinks). The files are the truth; index.db is how a two-second lookup finds them. Every hit is counted in a recall log, which ranks the always-loaded page. And since that page may omit things, this index is what guarantees every memory is reachable: lint checks at every session start that every memory file is in it.

The life of a session

Everything above serves one repeating unit of work: a session. It is born knowing the doctrine, works in a private context window, and dies leaving everything durable on disk. Birth is automatic, close-out is a ritual, and skipping the ritual is the only way to lose a day.

When does one session see another's work? Three answers. File writes: immediately. Save a contact, a status row or a memory, and every other session can read it; coordination happens by writing early. Conversation: at close-out. What was said in a window exists nowhere else until the ritual captures it as a card and pushes conclusions into their files. Unwritten context: never. A window cleared without capture takes its contents with it.

Two rules follow. One thread per channel, because live context is private, and a thread split across two sessions means neither has the whole picture. And /spinoff stages context to disk first: the child can't see the parent's conversation, so the parent writes a brief (sources, deliverables, constraints, death step) and the child's first act is to read it. Context transfer is a file, not a memory.

Other timers come and go with the work (a news scrape, a digest, a weekly evaluation batch), and every one has the same shape: a timer, a headless claude -p wrapper, and a confirmation token checked in the output. Everything runs on one always-on machine. Cloud scheduling was tried and retired: local means direct file access and one place to look when something misfires.

Why this and not fine-tuning

If the model needs to know this life, why not train it on this life? Three reasons, each sufficient. Weights can't take one-shot facts: one day's events are statistically invisible to training, and repeating them enough to stick damages what the model knows. Weights can't forget: a false belief smeared across parameters has no line number, while here a wrong memory was once caught, traced and deleted as one file. The frontier isn't yours to train: a personal fine-tune rides a lesser model; retrieval gets both.

The bet underneath: whatever the mechanism becomes, the curated, provenance-tracked corpus is the durable asset. It is the retrieval substrate of today and the training set of whenever. The organs keep it clean; the corpus compounds.

The derived index: decided 8/17, built 9/3

The always-loaded page used to be written by hand, one line per memory, and on 8/16 it ran out of room. Since 9/3 a program writes it, from the files, every Sunday night and after every consolidation.

How. Each memory carries a hook: in its header, the few words a fresh session needs to recognize it. The generator pins every feedback memory first (the rules for working with the principal), ranks the rest by how often recall used them in the last thirty days plus a bonus per inbound link and a floor for anything under a week old, and writes lines until the byte budget is hit. The names that didn't fit go in a trailer, so a session knows they exist.

What changes for the operator. "Nothing to archive" is the normal state now; archiving is only for memories that are wrong or superseded. To improve a line, edit the memory's hook, not the page. A memory that falls off the page is cooled, not gone: recall still finds it, and use earns the line back.

Where the safety net went. The page may now omit things by design, so lint no longer asks for a line per memory. Instead it checks the layer that finds the cooled ones: every memory on disk must be in the recall index, verified at every session start after sync runs, with a ten-minute grace for a file racing the start.

Appendix: principles of the index

"Some things come forth immediately; others must be sought longer, as though dug out of more secret receptacles; others rush out in troops, and while a different thing is asked, they leap into the midst, as if to say, is it perchance I? These I drive away from the face of my remembrance, until what I wish for be unveiled and appear out of its secret place."
Augustine, Confessions X. Hybrid retrieval, ranked candidates and a reranker, ca. 400 AD

The page is a list of lights, not a book. MEMORY.md exists so a fresh session recognizes: the light goes on, "I know this, go look." Title plus a few words of hook is the minimum unit; a bare name doesn't disambiguate, a paragraph is content smuggled into a cache. Detail lives in the file.

The reader determines the format. The page is read by a model in context; the stores are read by search. Aliases and alternate spellings go in file bodies, where literal matching needs the exact string. The page never spends capped bytes on fuzziness its reader supplies for free.

The model's prior is the codebook. Private notation is a false economy: it discards the prior that decompresses prose for free, needs decode instructions, and loses on tokens, since tokenizers are trained on prose. Plain language is the efficient encoding.

Structure where machines compute; prose where the model reads. People, companies and properties live in their own stores, and memory filenames carry their type prefix, so the tag rides for free. Format is cost when read into context, capability when computed over.

The compression frontier is selection, not encoding. Past lean hooks, bytes come from selection: a cold entry's recognition value decays while its byte cost stays constant. Since 9/3 that decay is measured. A memory's value is its recall count over thirty days, and leaving the page is rank, recomputed weekly. What leaves the page stays fully findable.

Enforced, not remembered. The pointer discipline used to be a write-time gate in the validator, because a page that outgrows its read limit fails invisibly. Since 9/3 there is nothing to enforce: the budget is how the page is generated, and nothing hand-writes it. Deterministic rules go in generators and hooks; judgment goes in reviews.

A failed grep proves little. Grep is the crudest of three recognition paths. A thing is unknown only when the page, automatic recall and deliberate search all miss, and the alias convention makes that rare.
